## Recommended execution order

1. **001** — one-line constant fix, zero risk, do first.
2. **002** — one-line accessibility guard, zero risk.
3. **004** — moderate scope (JSX restructure in `ProjectsSection.tsx`), no
   dependency on the others.
4. **005** — one-line className swap in `TypingGame.tsx`, no dependency on
   the others.
5. **003** — do last and treat as a judgment call, not a mechanical fix. It
   swaps the Hero tilt's easing curve from `--ease-out` to `--ease-in-out`;
   the plan itself flags that this needs a human feel-check before merging,
   since `--ease-in-out`'s slow-start character may or may not read better
   than the current fast-start feel for a cursor-follow effect.

## Dependencies between plans

None of the five plans touch overlapping code, and none depend on another
being applied first. They can be executed in any order or in parallel; the
order above is by risk/effort, not by requirement.

## Execution notes

All five plans were applied in order (001–005) at commit `01d027a`.
Mechanical verification (`npx tsc --noEmit`, `npm run lint`) passed clean
with no new errors after all five changes. Each diff matched its plan's
`Steps` exactly with no boundary violations.

**003 still needs a human feel-check.** The plan itself flags this as a
judgment call, not a mechanical fix — `--ease-in-out`
(`cubic-bezier(0.77, 0, 0.175, 1)`) starts *slow*, so the Hero portrait tilt
may now feel less responsive when the cursor first enters the image, even
though it's the textbook-correct curve for on-screen movement. Load the
homepage and move the mouse across the portrait before merging; revert to
`ease-[var(--ease-out)]` on `Hero.tsx:41` if it feels sluggish rather than
smooth.

The other four feel-checks (menu exit timing, reduced-motion mascot gating,
project filter crossfade, typing-test result entrance) are lower-risk and
were not separately re-verified in-browser as part of this pass — recommend
a quick manual pass per plan's Verification section before shipping.
